# Survive or Die

Аркадная игра на выживание в браузере: бегаешь, отбиваешься от толп, качаешь
апгрейды. Чистый JavaScript + Canvas, без фреймворков и сборки.

К 70-му дню — собственная пиксельная графика, кампания из четырёх локаций
с боссами и онлайн-таблица рекордов.

Учебный проект по вайбкодингу: **70 дней, по одному коммиту в день.**
План на все 70 дней — в [ROADMAP.md](ROADMAP.md).

## Играть онлайн

**https://filinhoo-afk.github.io/Survive_or_die/**

Сайт обновляется сам: каждый пуш в `main` запускает
[.github/workflows/deploy.yml](.github/workflows/deploy.yml), и через минуту
свежая версия уже открывается по ссылке. На сайт уходят только `index.html`,
`css/` и `src/` — сборки нет. Все пути в игре относительные, поэтому она
одинаково работает и с `localhost:8000`, и из подпапки `/Survive_or_die/`.

## Как запустить локально

Игра использует ES-модули, поэтому её нужно открывать через локальный сервер,
а не двойным кликом по `index.html`.

```bash
python -m http.server 8000
```

Затем открыть http://localhost:8000

## Тесты

Игровая логика проверяется встроенным в Node раннером `node:test` — без
зависимостей и без `npm install` (нужен Node 22 или новее):

```bash
npm test
```

Это то же, что `node --test`: он сам находит файлы `tests/*.test.js`, а один файл
запускается как `node --test tests/spawner.test.js`. Весь набор проходит меньше чем
за секунду.

## Линтер и проверка на каждый пуш

Линтер — [ESLint](https://eslint.org) с набором `recommended` ([eslint.config.js](eslint.config.js)).
Он ловит ошибки, а не спорит о стиле: необъявленные и неиспользуемые переменные, `var`,
нестрогое `==`, недостижимый код. Форматирование не проверяется. Игре линтер не нужен —
он стоит только как dev-зависимость, поэтому `npm test` по-прежнему работает без установки,
а для линтера нужен один раз `npm install`:

```bash
npm install
npm run lint    # только линтер
npm run check   # линтер и тесты — то же, что гоняет CI
```

[.github/workflows/ci.yml](.github/workflows/ci.yml) на каждый пуш и каждый pull request
ставит зависимости по `package-lock.json` (`npm ci`), запускает линтер и тесты на Node 22
(нижняя граница из `engines`) и Node 24. Новый пуш в ту же ветку отменяет ещё идущую
проверку. Красный значок у коммита на GitHub — повод чинить до следующего дня. Деплой на
Pages ([deploy.yml](.github/workflows/deploy.yml)) идёт отдельно и результата проверок не ждёт.

## Что покрыто тестами

Что покрыто, по папкам `src/`:

| Область | Что проверяется |
|---------|-----------------|
| Случайность и испытание дня | генератор `mulberry32` и его независимые потоки; сид, локация и герой дня заморожены цифрами — сервер считает по той же формуле |
| Сохранение и прогресс | переезд со старых ключей, битый JSON, недоступный `localStorage`; золото, рекорд, кампания, герой, никнейм, настройки |
| Бой | урон и броня игрока, опыт и уровни, попадания и пробитие снарядов, касания, смерть и крит врагов, стрелки |
| Оружие | уровни, бонусы пассивок, перезарядка, арсенал, карточки выбора, веса, эволюции по всем четырём рецептам |
| Мир | спавнер и кривая сложности, расстановка препятствий и столкновения, ящики и предметы, пространственная сетка (против перебора всех со всеми), пул |
| Язык | словари ru и en с одинаковыми ключами и подстановками, каждый символ рисуется шрифтом, данные игры переводятся на лету, выбор запоминается |
| Обучение | порядок шагов и их цели, кому показывать, пропуск, тексты помещаются в рамку на обоих языках |
| Достижения | пороги каждого, накопление между забегами, перенос из старого прогресса, тексты и карточки помещаются на экран |
| Онлайн | запросы к Supabase на поддельном `fetch`, отправка результата и все её отказы, место в рейтинге, таблица рекордов и откат без миграций |
| Данные | каждая локация, враг, декор и иконка ссылаются на существующий клип атласа; у боссов и стрелков есть всё нужное |

Часть модулей при загрузке рисует спрайты в `canvas`, которого в Node нет.
Тесты, которым нужны враги, игрок или оружие, первой строкой подключают
[tests/helpers/dom.js](tests/helpers/dom.js): он подменяет только сам холст, а пиксельные
карты разбираются по-настоящему, так что битая карта спрайта роняет тест.
[tests/helpers/storage.js](tests/helpers/storage.js) даёт чистый `localStorage` на каждый тест,
[tests/helpers/backend.js](tests/helpers/backend.js) — сервер, который отвечает по сценарию.
Случайность в тестах либо зафиксирована сидом, либо подменена `Math.random`, поэтому они
не мигают.

## Обучение

Первый забег идёт с подсказками внизу экрана: движение, автоатака, кристаллы,
выбор улучшения, ящики и цель забега. Мир при этом не останавливается: подсказка
сменяется, когда игрок сделал то, о чём она говорит (последние две — по таймеру).
Сделанное заранее засчитывается, но каждая подсказка висит не меньше 2,5 секунды,
чтобы её успели прочитать. `Enter` (на геймпаде `Y`) пропускает обучение целиком.

Пройдено ли обучение, лежит в сохранении. Пока оно не пройдено и не пропущено,
каждый новый забег начинает его заново. Тем, кто уже играл до его появления (есть
забеги, золото, покупки или пройденные локации), оно не показывается. Посмотреть
его снова — строка «Обучение» в настройках: включается на следующий забег. Шаги
описаны данными в [src/systems/tutorial.js](src/systems/tutorial.js), рисует их
[src/ui/tutorialHint.js](src/ui/tutorialHint.js).

## Достижения

Четырнадцать целей, которые остаются открытыми навсегда. Экран — `G` в главном
меню (на геймпаде `Back`), под строкой связи видно, сколько уже открыто. В забеге
открытое всплывает под таймером, а на экране итогов слева перечислено всё, что
досталось за этот забег.

| Достижение     | Условие |
|----------------|---------|
| Первая кровь   | убить первого врага |
| Живучий        | продержаться 5 минут |
| Ни царапины    | минута забега без урона |
| Жнец           | 500 убийств за один забег |
| Ветеран        | достичь 15 уровня |
| Арсенал        | носить 4 оружия сразу |
| Эволюция       | развить оружие в эволюцию |
| Охотник        | 10 элитных врагов за забег |
| Хозяин леса    | победить Лесного стража |
| Упокоение      | победить Некроманта |
| Ледоруб        | победить Ледяного червя |
| Конец Бездны   | победить Владыку Бездны |
| Легион         | 5000 убийств за всё время |
| Трое героев    | победить босса каждым из трёх героев |

Достижение — это данные в [src/systems/achievements.js](src/systems/achievements.js):
цель и функция, считающая по снимку забега, сколько уже набрано. В испытании дня
они открываются так же. Два накопительных («Легион» и «Трое героев») считают только
законченные забеги — гибелью или победой, как золото и рекорд; брошенный с паузы в
общий счёт не входит. Тем, кто играл раньше, при первом запуске открывается то, что
доказывают сохранённый рекорд и пройденные локации. Достижения живут только в этом
браузере и на сервер не отправляются.

## Настройки и геймпад

Экран настроек открывается по `O` в главном меню и на паузе. Три ползунка
громкости (общая, музыка, эффекты) меняются шагом в 10 % клавишами `A` / `D`
или кликом по полосе. Там же язык и обучение. Клавиши движения переназначаются: выбрать строку,
`Enter`, нажать новую клавишу — она становится основной, прежняя уходит в
запасную. Клавиши, занятые меню (`Esc`, `Enter`, `R`, `P`, `M`, `B`, `O`, `N`, `T`, `I`, `G`,
`1`–`3`), отклоняются. Отклоняется и клавиша, которую нельзя отнять: если у другого
действия она последняя, а его клавиши по умолчанию уже заняты, одна клавиша двигала бы
героя сразу в две стороны. Всё сохраняется между запусками.

Геймпад подхватывается сам: левый стик и крестовина двигают героя, в меню
они листают, `A` — выбрать (Enter), `B` — назад (Esc), `Start` — пауза,
`X` — магазин / в меню, `Y` — заново, `LB` — настройки, `RB` — испытание дня, `Back` — достижения; карточки улучшений —
`A` / `B` / `X` (1 / 2 / 3).

## Язык

Игра на русском и английском. Строка «Язык» в настройках (`O` в меню или на паузе)
переключает язык сразу, без перезагрузки; выбор лежит в сохранении. Пока игрок не выбирал,
язык берётся из браузера: русский — русскоязычным, всем остальным английский. В тестах и до
чтения сохранения язык русский.

Весь видимый текст живёт в словарях [src/i18n/ru.js](src/i18n/ru.js) и
[src/i18n/en.js](src/i18n/en.js), а код ссылается на него по ключу: `t('shop.gold', { gold: 15 })`
(подстановки `{имя}`; нет перевода — берётся русский, нет и его — виден сам ключ). Названия
врагов, оружия, апгрейдов, героев и локаций остались полями данных: `localize()` превращает
`title`, `description` и `text` в геттеры, которые читают словарь в момент обращения, поэтому
код вроде `type.title` не знает про переводы, а язык меняется на лету.

Чтобы добавить язык, нужен новый словарь с теми же ключами, запись в `LANGUAGES`
([src/i18n/index.js](src/i18n/index.js)) и буквы, которых ещё нет в пиксельном шрифте. Тест
[tests/i18n.test.js](tests/i18n.test.js) следит, чтобы ключи словарей совпадали, подстановки не
терялись, шрифт знал каждый символ перевода (в английском нет апострофов и скобок: шрифт
нарисовал бы вместо них «?»), а на ключи из кода было что ответить. Окно профилировщика (`F3`)
остаётся русским: это инструмент разработчика.

## Онлайн-рекорды

Рекорды хранятся в [Supabase](https://supabase.com): это Postgres с готовым
REST-адресом, поэтому своего сервера у игры нет. Игра ходит туда обычным
`fetch` — без библиотек и сборки ([src/online/backend.js](src/online/backend.js)).
Состояние связи видно в левом верхнем углу главного меню, а топ-10 каждой
локации — на экране рекордов (`T` в меню; больше убийств — выше, при равенстве
раньше тот, кто быстрее; золотом отмечены победы над боссом). После каждого забега
результат (локация, герой, время, убийства, уровень, урон, победа) уходит в
таблицу в фоне, а в углу экрана итогов видно, дошёл ли он или сервер его
отклонил. Без сети игра играется как обычно — рекорд просто не отправляется.

Когда сервер принял результат, игра спрашивает, какое он занял место
([src/online/rank.js](src/online/rank.js)), и показывает «Место: N из M» в левом
углу экрана итогов (золотом — если это десятка лучших). «Лучше» — по порядку
таблицы: больше убийств, при равенстве меньше времени. Обычный забег считает
сам сервер: два запроса с `Prefer: count=exact` — сколько результатов лучше и
сколько всего, строки не скачиваются, а новой миграции не нужно. В испытании
дня место считается среди игроков (у ника один лучший результат, как в его
таблице) и подписано «Место дня». Не получилось узнать — строки просто нет.

Никнейм задаётся в меню клавишей `I`: до 12 символов — латиница, кириллица,
цифры и одиночные пробелы или дефисы между ними (шрифт игры знает только
заглавные, поэтому ник хранится заглавными). Он лежит в сохранении, уходит
вместе с результатом и показан в таблице рекордов; без ника результат подписан
«—». Правило одно и то же в игре ([src/systems/nickname.js](src/systems/nickname.js))
и в базе (функция `nick_valid` в [003_nickname.sql](supabase/migrations/003_nickname.sql)),
так что подставить в таблицу произвольную строку нельзя. Фильтра грубых слов нет.
Пока миграция 003 не применена, игра шлёт результат без ника и читает таблицу
без имён — ничего не ломается.

## Испытание дня

`C` в главном меню (на геймпаде `RB`) запускает испытание дня: у всех игроков
мира в этот день одна локация, один герой и один мир. День считается по UTC;
всё остальное выводится из его номера — числа суток с 1970 года
([src/systems/daily.js](src/systems/daily.js)): сид — номер, умноженный на
2654435761 по модулю 2³², локация и герой берутся из разных бит сида.
Расписание нигде не хранится, а сид дня показан в меню рядом с названием локации.

Сид питает генератор [src/systems/rng.js](src/systems/rng.js) — два потока на
`mulberry32`. Поток волн зависит только от времени забега, поэтому у всех в
одну и ту же секунду выходят одни и те же враги, в одних и тех же местах, с
одними и теми же элитами. Второй поток разыгрывает расстановку ящиков,
выпадение предметов, атаки боссов и карточки улучшений. Мир у всех один, а
исход разный: он зависит от того, как играет человек. Частицы, тряска и звук
сид не трогают — на них остаётся `Math.random`.

Правила испытания:

- локации открыты всем, как бы далеко ни зашла кампания, но победа в испытании
  её не продвигает;
- постоянные улучшения из магазина не действуют, чтобы стартовать на равных;
- личный рекорд в испытании не ведётся — у него своя таблица;
- рестарт (`R`) остаётся испытанием, выход в меню возвращает прежнюю локацию.

Результат уходит в ту же таблицу `scores`, но с датой в колонке `daily` — у
обычных забегов она пуста, и каждая таблица читает только свои строки. Топ дня
открывается клавишей `C` на экране рекордов; в нём лучший результат каждого
игрока (по нику) — десять попыток одного человека не займут всю таблицу.
Сервер ([004_daily.sql](supabase/migrations/004_daily.sql)) принимает только
сегодняшнее или вчерашнее испытание (забег, начатый до полуночи, успевает дойти)
и сам пересчитывает локацию и героя дня функцией `daily_challenge`: «лёгкую»
локацию в таблицу испытания не подставить. Пока миграция 004 не применена,
испытание играется, но не отправляется (и не попадает по ошибке в таблицу
локации), а вкладка дня пишет «Не удалось загрузить таблицу».

Ключ в [src/config.js](src/config.js) публичный: его видит каждый, кто открыл
сайт. Данные защищает не он, а правила в базе
([001_scores.sql](supabase/migrations/001_scores.sql),
[002_plausibility.sql](supabase/migrations/002_plausibility.sql) и
[004_daily.sql](supabase/migrations/004_daily.sql)):

| Слой | Что делает |
|------|------------|
| Права на таблицу | игроку разрешено только читать и добавлять; `id` и время создания ставит сервер |
| Политики RLS | читать и добавлять строки могут все, менять и удалять — никто |
| Ограничения `check` | локация и герой — только существующие, числа — в разумных рамках, ник — по правилу `nick_valid` |
| Проверка правдоподобия | триггер перед вставкой сверяет результат с правилами игры и отклоняет невозможный; для испытания дня — ещё и дату, локацию и героя |

Проверка правдоподобия — функция `score_problem`: по локации и времени она
считает, сколько врагов вообще могло появиться, сколько у них было здоровья и
сколько опыта они могли дать. Не пройдут тысячи убийств за минуту, победа над
боссом до его появления или в Пустоши, где босса нет, убийства без урона,
урон больше всего здоровья врагов, уровень, на который не хватило бы опыта.
Границы посчитаны по коду игры с запасом — честный забег проходит всегда;
поменялся баланс — числа в миграции правятся вместе с ним.

Чтобы поднять свой бэкенд: создать проект в Supabase, выполнить по очереди
файлы миграций в SQL Editor, вписать Project URL и publishable-ключ в `online` в
`src/config.js`. Секретный ключ (`secret` / `service_role`) в игру класть нельзя.

Проверить правила глазами обычного игрока (в таблицу ничего не попадает:
правдоподобие проверяется вызовом `score_problem`, а не вставкой; формулы
испытания дня сверяются с игрой вызовом `daily_challenge`):

```bash
node supabase/check-access.mjs
```

## Эволюции оружия

Оружие на максимальном уровне вместе с нужной пассивкой превращается в новое.
Готовая эволюция всегда попадает в выбор при повышении уровня, а пассивка,
которой не хватает до рецепта, помечена на карточке «ключ к эволюции».

| Оружие | Пассивка      | Эволюция      | Что даёт |
|--------|---------------|---------------|----------|
| Пушка  | Сила          | Громобой      | три тяжёлых заряда, пробивают толпу |
| Нож    | Спешка        | Вихрь клинков | клинки во все восемь сторон |
| Щит    | Броня         | Бастион       | шесть тяжёлых шаров, сбивают вражеские снаряды |
| Аура   | Регенерация   | Святая земля  | шире, сильнее и лечит, пока жжёт врагов |

Мир больше экрана: 2880 × 1800 против видимых 960 × 540. Камера плавно
следует за игроком и прижимается к границам, не показывая пустоту за краем.
Положение в мире видно в HUD и на миникарте в правом верхнем углу.
